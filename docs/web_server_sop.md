# Web 服务器运维手册（SOP）

## 一、CPU 飙高排查流程

1. 确认现象：登录监控面板查看 CPU 曲线，确认是单核打满还是整体负载升高，同时记录持续时间。
2. 定位进程：执行 `top -c` 按 CPU 排序，找到占用最高的进程 PID 与命令行。
3. 定位线程：执行 `top -Hp <PID>` 查看线程级占用，记录高占用线程的 TID。
4. 保存现场：连续执行三次 `jstack <PID> > /tmp/stack_$(date +%s).log`（Java 应用），用于分析死循环与锁竞争。
5. 检查流量：查看 Nginx access log 的 QPS 与慢请求数量，确认是否由突发流量引起。
6. 检查慢查询与定时任务：确认是否有全量任务、缓存击穿或批量导入在高峰期执行。
7. 临时缓解：若影响可用性，先将该节点从负载均衡摘除，或对异常进程执行 `kill -15 <PID>` 优雅降级。
8. 复盘：将线程栈、监控曲线和访问日志归档到事件单，定位根因后提交修复方案。

## 二、Web 服务器重启流程

1. 重启前确认已摘除流量：在负载均衡或网关中下线该节点，观察 1 分钟无新请求进入。
2. 检查当前连接与关键进程状态，确认没有正在执行的发布任务或数据迁移任务。
3. 停止服务：按部署方式执行 `systemctl stop nginx` 或容器编排平台的滚动停止。
4. 等待 10 秒确认端口释放，执行 `ss -lntp | grep 80` 验证。
5. 启动服务：`systemctl start nginx`，随后检查 `systemctl status nginx` 与错误日志。
6. 健康检查：访问 `/health` 接口返回 200，静态资源与反向代理均正常。
7. 恢复流量：将节点重新加入负载均衡，观察 5 分钟错误率与响应时间。
8. 重启失败时立即回滚到上一版本，并升级为 P2 事件处理。

## 三、注意事项

- 严禁在未摘流量的情况下直接重启生产 Web 节点。
- 重启操作属于高危变更，必须经过双人复核并保留操作记录。
- 高峰期（09:00-11:00、19:00-21:00）禁止执行非紧急重启。
