# 数据库服务器运维手册（SOP）

## 一、内存泄漏排查流程

1. 观察趋势：查看监控中 7 天的内存曲线，确认是否为持续上涨且重启后回落，排除缓存预热导致的正常增长。
2. 定位进程：执行 `ps aux --sort=-%mem | head` 找到内存占用最高的数据库进程。
3. 连接数检查：查询当前连接数与会话数（如 `SHOW STATUS LIKE 'Threads_connected'`），确认是否由连接泄漏引起。
4. 缓冲区检查：检查 buffer pool、sort buffer、临时表大小等参数是否配置过大，结合 QPS 评估合理性。
5. 慢查询与临时表：开启慢查询日志，检查是否存在大结果集排序、全表扫描导致的内存膨胀。
6. 内存明细：使用 `pmap -x <PID>` 或性能分析工具观察堆内存分布，确认增长来自连接缓冲、查询缓存还是存储引擎。
7. 临时缓解：设置内存使用告警阈值，必要时在业务低峰期重启实例释放内存，并保留现场数据。
8. 根因修复：根据慢查询与大事务定位到具体 SQL 或连接池配置问题，修复后持续观察 48 小时。

## 二、数据库重启流程

1. 确认主从状态：执行 `SHOW REPLICA STATUS`，确认从库延迟在可接受范围内。
2. 通知业务方：提前告知重启窗口，停止写入类定时任务与批量作业。
3. 切换流量：将读流量切到从库，写流量短暂停止或切换到备主。
4. 优雅关闭：执行 `systemctl stop mysqld`，等待刷盘完成，禁止使用 `kill -9`。
5. 启动实例：`systemctl start mysqld`，检查错误日志中是否有恢复（recovery）报错。
6. 校验数据：检查主从同步状态、关键表行数与最近写入时间。
7. 恢复流量：逐步恢复读写流量，观察慢查询与连接数 10 分钟。
8. 记录变更：在变更系统中登记重启原因、耗时与影响范围。

## 三、注意事项

- 内存告警阈值建议设置为物理内存的 85%，连续 5 分钟超过阈值即触发告警。
- 生产库重启必须提前申请变更单，禁止在业务高峰期直接重启。
- 重启前必须确认备份可用，备份时间不超过 24 小时。
